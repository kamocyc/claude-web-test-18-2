# 地形改変ゲーム プロトタイプ

地形を自由に掘り、トンネルを通し、地質と向き合うゲームのプロトタイプ。
TypeScript + Three.js + Vite。

```bash
npm install
npm run dev      # http://127.0.0.1:5173
npm run typecheck
npm test
```

## これは何か

地質は 3 種類 (土 / 岩 / 軟弱層) と、水平な地下水位が一本だけ。
物性テーブルも安息角も無い。**色を見れば分かる**が唯一の要件。
その上で、次の判断が成立することを狙っている。

- 岩盤を狙って遠回りするか、軟弱層を突っ切って支保コストを払うか
- 調査に金をかけるか、勘で掘って事故るか
- 水位より下に潜るか、上を維持するために勾配を犠牲にするか

## 操作

| キー | ツール | |
|---|---|---|
| Q | 見る | 左ドラッグで回転 |
| W | 掘る | 左ドラッグで掘削。地質で掘進速度と費用が変わる。安息角より急な法面は崩れる |
| E | 盛る | 左ドラッグで盛土。残土から充当し、足りなければ購入。急に盛れば崩れる |
| A / S / D | 木枠 / 覆工 / 鋼製 | トンネルをなぞって支保を設置 |
| Z | 調査 | クリックでボーリング。周囲 9 m の地質が分かる |
| X | 断面 | 地表をドラッグして断面線を引く |
| `[` `]` | | ブラシ半径 |
| 0-3 | | 時間速度 (停止 / x1 / x2 / x4) |

掘るツール以外では右ドラッグで回転。

## 設計上の要点

### 1. プレイヤーにボクセルを気づかせない

これが技術的な最大要件で、実装順もこれを最初に証明する形にした。
斜めやカーブを掘っても階段状にならないこと、道路や線路として自然な
曲線と勾配が作れることが前提になる。

- ワールド全体で **1 本の密度場** (0.5 m セル / 128×64×128 m) を持ち、
  チャンクはその添字範囲を見るだけ。チャンクごとに独立した配列を持つと
  境界の頂点が一致せず必ず割れる。
- **Naive Surface Nets** でメッシュ化。セルごとに頂点 1 個をエッジ交点の
  重心に置く。Marching Cubes と違って針状三角形が出ない。
- **法線はノードで勾配を求めてから三線形補間する。** 頂点位置で直接
  中心差分すると、三線形場の勾配がセル境界で不連続なので格子状の
  陰影の筋が出る。ここが一番効く。
- ワールド座標ベースの**トライプラナー着色**。周期 (3.7 m / 1.13 m) を
  格子の 0.5 m とわざと揃わない値にしてある。
- ディテールの微分で法線を微妙に揺らす。ただし画素のワールド footprint で
  減衰させないと、遠景でノイズがエイリアスして階段状のゴミになる。
- 掘削は**スイープしたカプセルのスムーズ差**。ブレンド幅 0.5 m の
  フィレットが入るので、斜めのトンネルが山肌から自然にラッパ状に開口し、
  ストロークの継ぎ目も消える。

### 2. 密度場への書き込み口は 1 箇所だけ

`src/terrain/Edit.ts` の `applyCapsule()` しか密度場を書き換えない。
ここが影響 AABB と地質別の掘削体積を返すので、

- 再メッシュすべきチャンク
- 経済の記帳 (掘削費・残土)
- 再評価すべき構造物

がすべて同じ 1 つの信号から出る。取りこぼしが原理的に起きない。

### 3. 「崩落は後から地面が変わったときだけ」

`src/game/SpatialIndex.ts` の一様ハッシュを編集 AABB で引き、当たった
トンネル区間だけを再評価キューに積む。全区間を毎フレーム舐めない。

支保済みトンネルの真上を掘って土被りを削ると、必要支保レベルが上がって
劣化が始まる — という因果がこれで自動的に出る。特別扱いは書いていない。

### 4. トンネルであることの判定

タイルが無いので自分で決める必要がある。掘進の中心線を 2 m ごとの
区間として記録し、区間ごとに

- 断面リング 12 点の地質のうち**いちばん厳しいもの**を必要支保とする
  (岩 0 / 土 1 / 軟弱 2)。水位より下なら +1、土被りが薄ければ +1。
- 真上へレイマーチして土被りを測り、掘削半径の 1.5 倍未満なら
  「切土・坑口」として支保不要にする。

土被りを見ないと、ただ地面に掘った溝にまで支保を要求してしまう。

土被りは坑道の**天端から上へ、残った空洞を抜けてから**測ること
(`overburdenAt`)。スムーズ差のブレンド幅ぶん空洞が名目半径より広がるので、
`中心 + 半径` から素朴に測るとまだ坑道の中に入っていて、すぐ空気に当たり
土被り 0 と誤判定する。ちゃんと地中を掘っていてもトンネルとして
登録されなくなり、「掘っても何も起きない」になる。

掘る前の下見 (`previewBore`) も同じ物差しを使う。ここがずれると
「下見ではトンネルと言っていたのに掘ったらならない」が起きる。
坑口では土被りが 0 なのは当たり前なので、下見はカーソル位置だけを見ずに
掘進方向へ進みながら最初にトンネル成立する所を探し、
「あと N m でトンネル / 必要支保 X」として出す。

崩落は SDF への操作 2 つで表現できる。坑道を土砂で埋め戻し、土被りが
薄ければ真上に陥没孔を開ける。どちらも `Edit.ts` を通るので、そこから
さらに周囲の再評価が連鎖する。

**埋まった所を掘り直すと、また崩落する。** しかも埋め戻し材は軟弱層
(ずり) なので、元が土や岩だった区間は二度目のほうが必要支保が上がる。
特別扱いは書いていない。埋め戻しが地質を書き換え、掘り直すと新しい区間が
その地質を読む、というだけで自然にそうなる。掘り返すこと自体は速くて安い
(軟弱層なので)。「崩れたら片付けて巻き直す」がコストとして成立する。

なお、掘り返した場所の古い崩落マーカーは `recordBore` で片付ける。
崩落区間は再評価されないので放っておくと消えず、再開通した坑道の中に
暗いリングが浮いたまま、掘り直すたびに区間が増え続ける。
この片付けは土被り判定より**前**に置くこと。地表まで抜けた陥没の跡は
土被りが無いので、後ろに置くと弾かれていつまでも片付かない。

### 4a. リングの意味 — 色は「足りているか」、形は「何が入っているか」

リングは掘進の記録そのもの。**2 m ごとの区間 1 本につき 1 個**、
掘進方向に垂直な面に、そのとき使ったブラシ半径で置かれる。

**色 = 支保が足りているかどうか** (何が入っているかではない)

| 色 | 意味 |
|---|---|
| 橙 → 赤 に明滅 | `設置済み < 必要`。**崩落に向かっている** |
| 木枠の茶 / 覆工の灰 / 鋼製の青灰 | 必要を満たしている |
| くすんだ青灰 | 必要 0 (岩など)。無支保のままで足りている |
| 暗い赤 | 崩落済み |

明滅は健全度が落ちるほど速くなる (2 → 12 rad/s) ので、
**点滅の速さがそのまま余命**になる。橙から始めるのは、黄色だと
軟弱層 (黄) の壁に溶けて警告に見えないため。

判定順が大事で、「支保が入っているか」を先に見てはいけない。
木枠しか入っていないのに鋼製が要る区間が木枠の茶色で表示され、
劣化中なのに手当て済みに見えてしまう。

**形 = 何が入っているか**

| | 見た目 |
|---|---|
| 木枠 (L1) | 細いリングが飛び飛び。あいだから地山がそのまま見える |
| コンクリート覆工 (L2) | 連続した覆工チューブ。地山が完全に隠れる |
| 鋼製支保+排水 (L3) | 覆工チューブ + 太いリブ |

この 2 軸なので「赤い覆工チューブ」= 巻いてはあるが足りない、が読める。

支保不足の区間からは地表へ**警告柱**が伸びる (深度テストを切ってあるので
山の向こう側でも外から見える)。右上のパネルにも設置済みの内訳が出る。

### 4a-2. 支保はどこをクリックするか

**狙いは「カーソルのレイが貫く区間」で採る。地表のヒット点ではない。**
ヒット点で採ると、山の外から狙ったときヒット点は地表にあり、
坑道までは土被りぶん (5〜15 m) 離れているので何も選べない。
警告柱が外から見えているのに押しても何も起きない、という状態になる。

- レイから **ブラシ半径の 1.6 倍 (約 4 m)** 以内にある区間から選ぶ
- 選ばれた区間を中心に **前後 2.2 倍 (約 6 m)** の区間へまとめて予約する
- つまり **坑道の中を狙う / 山の外から警告柱を狙う** のどちらでもよい
- 狙っている区間は水色の輪で示される (地形を透かして見える)
- 必要支保 0 の区間と、資金不足のときは予約されない

**警告柱は根元だけでなく全長が当たり判定になっている。**
区間の中心点との距離で判定すると、拾い半径ぶんの高さまでしか届かず、
柱の下 3 割しか押せない。柱を線分として扱うこと (`rayToVertical`)。
柱の高さは `beamHeight()` に集約してあり、描画と当たり判定で必ず同じ値を使う。
ずれると「見えている柱を狙っても取れない」が起きる。

**視線上に区間が重なっているときは、まだその支保を入れられる区間を優先する。**
単純に手前を採ると、処置済みの区間が奥の未処置の区間を覆い隠して
いつまでも奥に届かない。

### 4a-3. 押してから実際に入るまでは時間がかかる

施工班は 1 班しかいないので、予約は**直列の待ち行列**になる。
費用は押した瞬間に引かれるが、支保が入るのはその区間の順番が来てから。

| | 1 区間あたり |
|---|---|
| 木枠 | 0.4 時間 |
| コンクリート覆工 | 1.2 時間 |
| 鋼製支保+排水 | 2.2 時間 |

7 区間を鋼製で予約すると、最後の 1 本が入るのは 11.4 時間後になる。
これは仕様 (長いトンネルを一気に掘ると施工が追いつかない、という緊張) だが、
**押した瞬間に金だけ減って見た目が変わらないと「効いていない」と思われる**ので、

- HUD に `施工 コンクリート覆工 あと 6.6 時間` と、その区間の見込みを出す
- リングの色を、危険色から予定の支保色へ寄せた中間色にする
  (手配済みだが未着。まだ崩落しうる事実は隠さない)
- 右上のパネルに `施工待ち N`

### 4b. 崩落は必ず予告される

健全度が落ちてから知らせたのでは遅い。支保が不足しているという事実は
**掘った (あるいは土被りが減った) 瞬間に確定する**ので、その時点で警告する。
一時停止中でも検出は走る。

- 掘っている最中にトーストが出る — 「軟弱層 — 鋼製支保+排水 が必要 / あと 8.8 時間」
- 右上のパネルが赤くなり、**割合ではなく残り時間**を主役に出す。
  「あと何時間で崩落」のほうが、支保を入れるか掘り進むかの判断に直結する。
- 危険な区間から地表へ**警告柱**が立つ。深度テストを切ってあるので
  山の向こう側で崩れかけていても外から気づける。崩落が近いほど速く明滅する。

1 段階不足なら余命 80 時間 (不足段階の 2 乗で縮む) あるので、
警告を見てから支保を入れれば十分間に合う。間に合わないのは、
長いトンネルを一気に掘って施工班 1 班では追いつかないときだけ。

### 4c. 安息角 — 急な法面は自重で崩れる

土は垂直には立たない。掘って安息角より急になった法面は、時間をかけて
崩れ、削れた土砂は法尻に溜まる。地質ごとに立てる角度が違うので、
**地上の判断がそのまま地形の形として出る**。

| 地質 | 安息角 | 切土の法面 | 用地 | 掘削費 |
|---|---|---|---|---|
| 岩 | 78° | ほぼ直立のまま | 狭い | 高い |
| 土 | 34° | 寝る | 広い | 中 |
| 軟弱層 | 26° | よく寝る | 非常に広い | 安い |
| 軟弱層・水位下 | 18° | 極端に寝る | 最悪 | 安い |

「掘るのは安いが法面が寝るので用地と手間を食う」が数字ではなく形で分かる。

**セル単位のセルオートマトン (砂山 CA) は使っていない。** 立方格子上の CA は
安定斜面が格子方向に量子化され、崩れた山が四角錐になる。要点 1 を真っ向から
壊すので採れない。代わりに、崩落を「安息角の平面 ∩ 影響球での滑らかな
CSG 切り取り」として表す。切る平面の向きは密度場の勾配から来る連続量なので、
格子とはまったく関係しない。使う演算子はプレイヤーの掘削と同じ `applyShape`。

崩れた土砂は **側面が安息角の円錐** として法尻に積む。球を置くと地面と交わる所の
接線が立ってしまい、置いた瞬間にそこがまた「急すぎる法面」になって、
土が延々と歩き回って止まらなくなる (実際そうなった)。砂を落とすと円錐になる、
という当たり前の形がそのまま答えになっている。

削った量と積んだ量は実測して突き合わせ、`削った量 = 積んだ量 + 未処理の負債`
を恒等式として保つ。ここが崩れて土が湧くと、増えた土がまた崩れて永久に止まらない。

**触っていない地山は安息角 + 14° まで立つ。** 安息角は「ほぐれた土が自然に積もる
角度」であって、締まって根の張った地山がその角度でしか立てないわけではない。
生成される自然地形は中央値 30°・4 割が 34° 超なので、この上乗せが無いと
斜面のどこを 1 回掘っても周囲がまとめて崩れる (実測で掘削 250 m³ に対し
6300 m³ が動いていた)。崩落そのものも自分の通り道を「緩んだ地山」に
書き換えない。書き換えると地滑りが自分で道を塗りながら斜面を登り続ける。

### 5. 分からないものは見せない

地質の既知/未知はセル単位では保存しない。描かれている地表は定義上
すべて露出面なので、見えている所は常に真の色でよい。分からないのは
「まだ掘っていない面の裏側」だけなので、保持するのはボーリングの
柱状図だけで足りる。

断面ビューは、各画素の信頼度を「露出面からの距離」と「ボーリングからの
距離」の大きいほうで決め、低い所を灰色ハッチに落とす。密度場の値が
ほぼ「表面までの距離」なので、掘った坑道の壁も自動的に露出面として
扱われる。トンネルを掘れば周囲の地質が分かるようになる。

## 検証

- `npm test` — 純粋な部分を数値で固定している (29 件)。
  - 隣接チャンクの共有境界で頂点位置がミクロン以内、法線と地質重みが
    ビット単位で一致すること。ここが壊れると地形に割れが出るが、
    描画を見て気づくのは難しい。
  - 必要支保レベルの判定規則。
  - ボーリングの層序と信頼度。
  - **安息角**: 高さ 6 m・傾き 81° の法面が静止するまで回して、通しの角度を実測する。
    岩 78° → 80.5 / 土 34° → 29.8 / 軟弱 26° → 23.7 / 軟弱・水位下 18° → 18.9。
    体積保存 (恒等式)、有限 tick での停止、伝播の打ち切りも合わせて固定。
    「なんとなく寝た」では確認にならないので数値で押さえている。
- 見た目は Playwright でスクリーンショットを撮って確認する。
  `window.__game` に `view()` / `carve()` / `bore()` のデバッグ API がある。
  `?mat=plain` `?mat=normal` でシェーダを外し、格子が見える原因が
  ジオメトリ側かシェーダ側かを切り分けられる。
