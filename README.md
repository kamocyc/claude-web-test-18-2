# 地形改変ゲーム プロトタイプ

地形を自由に掘り、トンネルを通し、地質と向き合うゲームのプロトタイプ。
TypeScript + Three.js + Vite。

```bash
npm install
npm run dev      # http://127.0.0.1:5173
npm run typecheck
npm test
```

## これは何か

地質は 3 種類 (土 / 岩 / 軟弱層) と、水平な地下水位が一本だけ。
地質ごとに持っている数値は、掘進速度・単価・必要支保レベル・**安息角**だけ。
**色を見れば分かる**が唯一の要件。その上で、次の判断が成立することを狙っている。

- 岩盤を狙って遠回りするか、軟弱層を突っ切って支保コストを払うか
- 調査に金をかけるか、勘で掘って事故るか
- 水位より下に潜るか、上を維持するために勾配を犠牲にするか
- 法面が寝るぶんの用地を払うか、岩を選んで法面を立てるか
- 曲がれる規格で地形に沿うか、曲がれない規格で尾根を切り谷を跨ぐか
- 谷を短支間で渡って軟弱層に橋脚を落とすか、長支間で跨ぐか、深礎で岩まで下ろすか

## 設計上の要点

### 1. プレイヤーにボクセルを気づかせない

これが技術的な最大要件で、実装順もこれを最初に証明する形にした。
斜めやカーブを掘っても階段状にならないこと、道路や線路として自然な
曲線と勾配が作れることが前提になる (それを実際に作るのが §4f / §4g)。

- ワールド全体で **1 本の密度場** (0.5 m セル / 128×64×128 m) を持ち、
  チャンクはその添字範囲を見るだけ。チャンクごとに独立した配列を持つと
  境界の頂点が一致せず必ず割れる。
- **Naive Surface Nets** でメッシュ化。セルごとに頂点 1 個をエッジ交点の
  重心に置く。Marching Cubes と違って針状三角形が出ない。
- **法線はノードで勾配を求めてから三線形補間する。** 頂点位置で直接
  中心差分すると、三線形場の勾配がセル境界で不連続なので格子状の
  陰影の筋が出る。ここが一番効く。
- ワールド座標ベースの**トライプラナー着色**。周期 (3.7 m / 1.13 m) を
  格子の 0.5 m とわざと揃わない値にしてある。
- ディテールの微分で法線を微妙に揺らす。ただし画素のワールド footprint で
  減衰させないと、遠景でノイズがエイリアスして階段状のゴミになる。
- 掘削は**スイープしたカプセルのスムーズ差**。ブレンド幅 0.5 m の
  フィレットが入るので、斜めのトンネルが山肌から自然にラッパ状に開口し、
  ストロークの継ぎ目も消える。

### 2. 密度場への書き込み口は 1 箇所だけ

`src/terrain/Edit.ts` の `applyCapsule()` しか密度場を書き換えない。
ここが影響 AABB と地質別の掘削体積を返すので、

- 再メッシュすべきチャンク
- 経済の記帳 (掘削費・残土)
- 再評価すべき構造物

がすべて同じ 1 つの信号から出る。取りこぼしが原理的に起きない。

### 3. 「崩落は後から地面が変わったときだけ」

`src/game/SpatialIndex.ts` の一様ハッシュを編集 AABB で引き、当たった
トンネル区間だけを再評価キューに積む。全区間を毎フレーム舐めない。

支保済みトンネルの真上を掘って土被りを削ると、必要支保レベルが上がって
劣化が始まる — という因果がこれで自動的に出る。特別扱いは書いていない。

### 4. トンネルであることの判定

タイルが無いので自分で決める必要がある。掘進の中心線を 2 m ごとの
区間として記録し、区間ごとに

- 断面リング 12 点の地質のうち**いちばん厳しいもの**を必要支保とする
  (岩 0 / 土 1 / 軟弱 2)。水位より下なら +1、土被りが薄ければ +1。
- 真上へレイマーチして土被りを測り、掘削半径の 1.5 倍未満なら
  「切土・坑口」として支保不要にする。

土被りを見ないと、ただ地面に掘った溝にまで支保を要求してしまう。

土被りは坑道の**天端から上へ、残った空洞を抜けてから**測ること
(`overburdenAt`)。スムーズ差のブレンド幅ぶん空洞が名目半径より広がるので、
`中心 + 半径` から素朴に測るとまだ坑道の中に入っていて、すぐ空気に当たり
土被り 0 と誤判定する。ちゃんと地中を掘っていてもトンネルとして
登録されなくなり、「掘っても何も起きない」になる。

掘る前の下見 (`previewBore`) も同じ物差しを使う。ここがずれると
「下見ではトンネルと言っていたのに掘ったらならない」が起きる。
坑口では土被りが 0 なのは当たり前なので、下見はカーソル位置だけを見ずに
掘進方向へ進みながら最初にトンネル成立する所を探し、
「あと N m でトンネル / 必要支保 X」として出す。

崩落は SDF への操作 2 つで表現できる。坑道を土砂で埋め戻し、土被りが
薄ければ真上に陥没孔を開ける。どちらも `Edit.ts` を通るので、そこから
さらに周囲の再評価が連鎖する。

**埋まった所を掘り直すと、また崩落する。** しかも埋め戻し材は軟弱層
(ずり) なので、元が土や岩だった区間は二度目のほうが必要支保が上がる。
特別扱いは書いていない。埋め戻しが地質を書き換え、掘り直すと新しい区間が
その地質を読む、というだけで自然にそうなる。掘り返すこと自体は速くて安い
(軟弱層なので)。「崩れたら片付けて巻き直す」がコストとして成立する。

なお、掘り返した場所の古い崩落マーカーは `recordBore` で片付ける。
崩落区間は再評価されないので放っておくと消えず、再開通した坑道の中に
暗いリングが浮いたまま、掘り直すたびに区間が増え続ける。
この片付けは土被り判定より**前**に置くこと。地表まで抜けた陥没の跡は
土被りが無いので、後ろに置くと弾かれていつまでも片付かない。

### 4a. リングの意味 — 色は「足りているか」、形は「何が入っているか」

リングは掘進の記録そのもの。**2 m ごとの区間 1 本につき 1 個**、
掘進方向に垂直な面に、そのとき使ったブラシ半径で置かれる。

**色 = 支保が足りているかどうか** (何が入っているかではない)

| 色 | 意味 |
|---|---|
| 橙 → 赤 に明滅 | `設置済み < 必要`。**崩落に向かっている** |
| 木枠の茶 / 覆工の灰 / 鋼製の青灰 | 必要を満たしている |
| くすんだ青灰 | 必要 0 (岩など)。無支保のままで足りている |
| 暗い赤 | 崩落済み |

明滅は健全度が落ちるほど速くなる (2 → 12 rad/s) ので、
**点滅の速さがそのまま余命**になる。橙から始めるのは、黄色だと
軟弱層 (黄) の壁に溶けて警告に見えないため。

判定順が大事で、「支保が入っているか」を先に見てはいけない。
木枠しか入っていないのに鋼製が要る区間が木枠の茶色で表示され、
劣化中なのに手当て済みに見えてしまう。

**形 = 何が入っているか**

| | 見た目 |
|---|---|
| 木枠 (L1) | 細いリングが飛び飛び。あいだから地山がそのまま見える |
| コンクリート覆工 (L2) | 連続した覆工チューブ。地山が完全に隠れる |
| 鋼製支保+排水 (L3) | 覆工チューブ + 太いリブ |

この 2 軸なので「赤い覆工チューブ」= 巻いてはあるが足りない、が読める。

支保不足の区間からは地表へ**警告柱**が伸びる (深度テストを切ってあるので
山の向こう側でも外から見える)。右上のパネルにも設置済みの内訳が出る。

### 4a-2. 支保はどこをクリックするか

**狙いは「カーソルのレイが貫く区間」で採る。地表のヒット点ではない。**
ヒット点で採ると、山の外から狙ったときヒット点は地表にあり、
坑道までは土被りぶん (5〜15 m) 離れているので何も選べない。
警告柱が外から見えているのに押しても何も起きない、という状態になる。

- レイから **ブラシ半径の 1.6 倍 (約 4 m)** 以内にある区間から選ぶ
- 選ばれた区間を中心に **前後 2.2 倍 (約 6 m)** の区間へまとめて予約する
- つまり **坑道の中を狙う / 山の外から警告柱を狙う** のどちらでもよい
- 狙っている区間は水色の輪で示される (地形を透かして見える)
- 必要支保 0 の区間と、資金不足のときは予約されない

**警告柱は根元だけでなく全長が当たり判定になっている。**
区間の中心点との距離で判定すると、拾い半径ぶんの高さまでしか届かず、
柱の下 3 割しか押せない。柱を線分として扱うこと (`rayToVertical`)。
柱の高さは `beamHeight()` に集約してあり、描画と当たり判定で必ず同じ値を使う。
ずれると「見えている柱を狙っても取れない」が起きる。

**視線上に区間が重なっているときは、まだその支保を入れられる区間を優先する。**
単純に手前を採ると、処置済みの区間が奥の未処置の区間を覆い隠して
いつまでも奥に届かない。

### 4a-3. 押してから実際に入るまでは時間がかかる

施工班は 1 班しかいないので、予約は**直列の待ち行列**になる。
費用は押した瞬間に引かれるが、支保が入るのはその区間の順番が来てから。

| | 1 区間あたり |
|---|---|
| 木枠 | 0.4 時間 |
| コンクリート覆工 | 1.2 時間 |
| 鋼製支保+排水 | 2.2 時間 |

7 区間を鋼製で予約すると、最後の 1 本が入るのは 11.4 時間後になる。
これは仕様 (長いトンネルを一気に掘ると施工が追いつかない、という緊張) だが、
**押した瞬間に金だけ減って見た目が変わらないと「効いていない」と思われる**ので、

- HUD に `施工 コンクリート覆工 あと 6.6 時間` と、その区間の見込みを出す
- リングの色を、危険色から予定の支保色へ寄せた中間色にする
  (手配済みだが未着。まだ崩落しうる事実は隠さない)
- 右上のパネルに `施工待ち N`

### 4b. 崩落は必ず予告される

健全度が落ちてから知らせたのでは遅い。支保が不足しているという事実は
**掘った (あるいは土被りが減った) 瞬間に確定する**ので、その時点で警告する。
一時停止中でも検出は走る。

- 掘っている最中にトーストが出る — 「軟弱層 — 鋼製支保+排水 が必要 / あと 8.8 時間」
- 右上のパネルが赤くなり、**割合ではなく残り時間**を主役に出す。
  「あと何時間で崩落」のほうが、支保を入れるか掘り進むかの判断に直結する。
- 危険な区間から地表へ**警告柱**が立つ。深度テストを切ってあるので
  山の向こう側で崩れかけていても外から気づける。崩落が近いほど速く明滅する。

1 段階不足なら余命 80 時間 (不足段階の 2 乗で縮む) あるので、
警告を見てから支保を入れれば十分間に合う。間に合わないのは、
長いトンネルを一気に掘って施工班 1 班では追いつかないときだけ。

### 4c. 安息角 — 土は垂直に立たない

掘って安息角より急になった法面は、**その場で**崩れて法尻に溜まる。
ゲーム内時間はかけない (時間を止めていても崩れる)。崩れた跡は
**厳密な平面**になる。

| | ゆるんだ土砂 (安息角) | 手つかずの原地盤 |
|---|---|---|
| 岩 | 78° | 88° |
| 土 | 34° | 85° |
| 軟弱層 | 30° | 80° |

水位より下ではどちらも 8° 寝る。軟弱層を水位下で掘ると法面は 22°、
つまり深さ 1 に対して幅 2.5 の用地を食う。

軟弱層の 30° は、軟らかい粘性土そのものとしては少し急めの値。そうしてある
のは、崩れて動いた土は元が何であれ軟弱層になるので、この値が**あらゆる
崩積土が最後に落ち着く角度**を兼ねているため。粘性土単体なら 26° でも
妥当だが、崩積土の代表値としては低すぎる (現実のズリ山や崖錐は 35-40°)。
1 つの値で両方を受け持つ以上、中央寄りに置いてある。

#### なぜ「列の高さ」で解くのか

欲しいのは「崩れたあとが平面であること」で、それは

```
|grad h| <= tan(θ)
```

という制約そのもの。**2 次元の高さ場**の上でこの制約を解けば、
停留点が定義から平面になる。3 次元の密度場のまま「急な所を球で削って
下に積む」をやると、削る形と積む形の選び方に答えが依存して凸凹が残る
(実装を試したうえで捨てた。積んだ山が傘状に取り残されてキノコになる)。

- `HeightIndex` が密度場を「列 (x,z) ごとの最上面の高さ」として読む
- `Repose` がその高さ場を安息角まで緩和する
- `Edit.applyColumnHeights()` が結果を
  `d = (h - y) / sqrt(1 + |grad h|^2)` として密度場に書き戻す。
  これは **Generator が初期地形を作るのに使っているのと同じ式**なので、
  整定した法面は周りの地形と地続きで、格子も出ない

1 列ぶんの緩和は「水位合わせ」で解く。超過分の半分を隣に渡す素朴な方式だと
制約面へ**漸近**するだけで、途中で止めた形が波打つ。全近傍の制約を同時に
満たす位置へ 1 回で落とすと、触った瞬間に平面に乗る
(実測: 同じ切土で演算量 1/25、平面性の残差 4e-4 m)。

#### なぜ角度が 2 つあるのか

安息角ひとつでは**崩落が止まらない**。法尻をひと掘りしたときの後退量は

```
法面の高さ / (tan(安息角) - tan(自然斜面の角度))
```

で、自然斜面が安息角に近いほど発散する。実測では 30° の斜面の裾を
1560 m³ 掘っただけで **41 m** 後退し、斜面がまるごと動いた。

そこで原地盤には別の (ほぼ垂直な) 自立角を持たせ、**掘った所だけ**を
「ゆるんだ土砂」に変える。ゆるんだ土砂は急な原地盤の上には留まれないので
流れ落ちて厚みがゼロに戻り、そこから先は原地盤の角度で止まる。
**止める規則を書かなくても止まる。**

原地盤の角度をほぼ垂直にしてあるのは、この値が受け持つのが
「**掘っていない地面がどこまで巻き添えになるか**」だけだから。掘った所は
必ず安息角まで寝るので、法面の見た目はこの値に依存しない。中途半端な値
(58°) にすると、斜面にトンネルが掘れなくなる — 坑口の開いた区間は深さ
5.2 m の溝なので、その上流の地山が 5.1 m 後退し、**崩落前線が掘削ヘッドより
先に進んで**土被りが付く前に天端が消える。実測 (30° の斜面へ 15 m 掘進):

| 原地盤の角度 | 到達した土被り | 掘削量 | 動いた土量 |
|---|---|---|---|
| 58° | 0 m (トンネルにならない) | 1601 m³ | 6872 m³ |
| 80° | 0 m | 828 m³ | 1613 m³ |
| **85°** | **5.7 m** | 459 m³ | **62 m³** |

### 4d. どこまでが「乱された地面」か

ゆるみの**厚み**は、その列で**実際に地表が下がった量**で決める
(編集の AABB の深さではない。AABB は形を 4.1 m 膨らませたものなので、
1 m³ も減っていない横の列まで同じだけゆるませてしまう。実測で、
1 フレームに掘れる 50 m³ に対して 330 m³ が armed になっていた)。

ただし地表が下がるのは**掘った穴の底**で、寝てほしいのはその**壁**。
壁の列は地表が下がらないので、低下量だけでは 87° で立ったままになる。
そこでゆるみを横へ広げる:

```
loose[隣] >= loose[自分] - 距離 * tan(安息角)
```

広げる距離は「その深さの法面が安息角で寝るのに要る幅」= 深さ/tan(安息角)
そのもの。任意の半径を決め打ちする必要が無く、**有限で止まる**。

広げてよいのは 2 つの条件を満たす列だけ:

- **過去に一度でも掘削がその列の地表まで届いた** (`reachMax`)。届いていない
  列はこれから坑道になる地山であって切土の法面ではない。「今の掘削の上端」
  ではなく「これまでの最大」を見るのは、深い切土は何度も掘り下げるから
  (今の上端だけだと 2 回目以降で壁が原地盤のまま立ち尽くす)
- **下に空洞が無い**。坑口の溝と、その奥の坑道は形としては同じ深い溝で、
  区別できるのは上に地山が架かっているかどうかだけ

どちらも掘削の形からしか立たない。崩落では伝染しないので、
先行実装の「旗が自分で斜面を塗り上がる」失敗にはならない。

「掘った所」を旗で覚えておく方式は駄目で、旗が下流の受け手に伝染して
地滑りが自分で斜面を塗り上がってしまう (これも試したうえで捨てた)。
ゆるみは**厚み**として持ち、動いた土といっしょに運ばれる必要がある。

ゆるんだ土砂の地質は原地盤とは別に持つ。一緒にすると、岩の急斜面に土が
薄く乗っただけでその列が「土」になり、岩の崖が丸ごと 34° まで崩れる。

#### 崩れて積もった土は崩積土 (軟弱層)

**動いた土は、元が土でも岩でも軟弱層になる。** ほぐれて積み直された土は
元の地山とは別物だからで、トンネル崩落の埋め戻し材 (`Tunnel.collapse` が
`Geo.Weak` を入れている) と同じ扱いに揃えてある。

これだけで連鎖が繋がる。崩積土は `GEO_SUPPORT_REQ` が 2 なので、
**崩れた跡を掘り直すと二度目のほうが必要支保が上がる**。掘るのは速くて
安いが (軟弱層なので)、支保は高くつく。特別扱いは書いていない。
色も軟弱層の黄になるので、どこが崩れて溜まった土なのかが一目で分かる。

崩積土になるのは**積もった土だけ**。削れて露出した面は元の地質のまま
(そこは掘り出された地山であって、動いた土ではない)。
表層の地質を書き換えるのも「新しく来た土のほうが多いとき」だけで、
薄く乗っただけで岩の急斜面が軟弱層の角度で崩れ出すのは避けている。

#### 起動時に世界を一度均す

生成直後の地形には原地盤の自立角より急な所がまだ残っている。
メッシュ化の**前**に一度整定して、世界を最初から釣り合った状態にしておく
(実測 0.9 秒 / 2700 m³)。掘っていない所が突然崩れることが原理的に無くなる。
均すのは自立角なので、谷も尾根も設計どおり残る (尾根の天端は 0.1 m も痩せない)。

#### 坑道を埋めないための規則

- 削る側は `min` しか使わない。値を下げるだけなので、下に坑道があっても
  **絶対に埋まらない**
- 積む側は空洞の天端に届く手前で止める
- 削る側も、**閉じた**空洞の天端には土被りを 1 m 残す。
  ただし守るのは閉じた空洞だけ。ブラシは円筒なので切土のふちには必ず庇が残り、
  その下も空洞に見える。これを坑道と同じに守ると、切土のふちが厚さ 1 m の
  庇で凍りついて法尻に垂直な壁が立ったままになる (実測 83.8°)。
  隣の列の地表がその空洞の天端より低ければ、その空洞は外へ通じている
  ＝ 坑道ではないので、庇ごと削ってよい

法面が崩れて土被りが減れば必要支保が上がって劣化が始まる、という連鎖は
書き戻しが `Edit.ts` を通ることで追加の配線なしに繋がる。
崩落は掘削ではないので経済には通さない (土量は保存しているので残土も動かない)。

#### 格子を見せないための近傍

安定な勾配の集合は内接半径 tan θ の正 M 角形になるので、近傍の取り方が
そのまま安定角の方位差になる。4 近傍だと 34.0-43.7° (崩れた山が四角錐になる)、
8 近傍で 34.0-36.1°、ナイト跳びを足した **16 近傍で 34.0-34.9°**。
16 近傍を使い、さらに公称値が最小ではなく真ん中に来るよう全体を
`2cos(π/M)/(1+cos(π/M))` 倍してある。円錐に崩した山の安定角は
実測で方位差 1.5° 未満。

距離は chamfer の近似整数ではなく実測値を使う。整数近似は距離変換を
整数演算で回すための工夫で、ここは tan を掛けるので近似する意味が無い。

### 4e. 法面保護工 — 崩れる前に払って止める

安息角を入れると、掘れば法面は必ず安息角まで寝る。深い切土ほど横へ広く
用地を食う。それを受け入れるしかない状態だと、崩落はただの理不尽になる。
**掘る前に塗っておけば、その角度で立つ。**

| | 支える角度 | 円 / m² | 時間 / m² | ブラシ 1 回 (21 m²) |
|---|---|---|---|---|
| 種子吹付 | 45° | 40 | 0.006 | ¥850 / 0.13 h |
| 法枠 | 65° | 180 | 0.02 | ¥3,800 / 0.42 h |
| 擁壁 | 88° | 500 | 0.06 | ¥10,500 / 1.26 h |

支保と同じ形にしてある。3 段階、費用は前払い、色 = 工法 / 中間色 =
手配済みだが未着。ブラシ 1 回の費用も支保 (¥900 / ¥4,200 / ¥11,000) と
同じ桁に揃えてあり、どちらかだけが実質選べない状態にならないようにしている。

**施工班は支保と共有の 1 班** (`src/game/Crew.ts`)。押した順に 1 本ずつしか
進まないので、「トンネルの支保を急ぐか、法面を押さえるか」がそのまま選択に
なる。キューを TunnelNetwork の中に置いたままにすると、支保専用の列と
保護工専用の列ができて班が 2 つあるのと変わらないので、外へ出してある。

崩落側への差し込みは 1 か所だけ。`Repose.pourColumn` が使う角度を
`max(いまの角度, 保護工の角度)` にする。保護工は「その面をその角度で支える
構造物」なので、ゆるみ土砂にも原地盤にも同じように効く。

**掘り崩したら保護工も消える** (その列の地表が 1 セル以上下がったら外れる)。
壁を掘り壊したのだから当然で、これがあるので「坑口まわりを塗ってから、
その中を掘り抜く」という段取りが成立する。塗った中を掘れば、掘った列だけ
保護が外れて周りは立ったまま残る。

見た目は地表に薄い板を重ねる。板の隅の高さは**まわり 4 列の平均**を採る。
列の高さで水平な板を置くと、法面で板が階段状に並んで格子がそのまま
見えてしまう (このプロトタイプの最優先要件に反する)。隅を共有させれば
隣の板と高さが一致して面が繋がる。

### 4f. 線形 — 規格が先、地形はあと

道路が地形と噛み合うのは、線形が地形に従うからではない。線形のほうに
**これ以上は曲がれない / 登れない**という規格があり、従えない所を
切土・盛土・トンネル・橋で埋めるからで、この順序が逆になると
ただの「地面をなぞる帯」になって判断が何も生まれない。

だから制御点は「**どこを通したいか**」でしかない。「どこを通るか」は
規格から解き直す。

| | 山岳道路 | 標準道路 |
|---|---|---|
| 最小曲線半径 | 18 m | 45 m |
| 最大縦断勾配 | 10 % | 6 % |
| 縦断曲線半径 | 160 m | 420 m |
| 路面幅 | 6.5 m | 9 m |
| 舗装 | ¥55/m² | ¥95/m² |

同じ 3 点で比べると、山岳 = 切土 13,540 m³ / ¥143,444、
標準 = 切土 17,634 m³ / ¥219,754。**曲がれないぶん地形を切ることになる。**

#### 制約を「測って警告する」のではなく「解く」

安息角 (§4c) と同じ考え方にしてある。欲しいのは

```
平面: |曲率| <= 1/Rmin
縦断: |dy/ds| <= imax  かつ  |d²y/ds²| <= 1/Rv
```

という制約そのもの。スプラインで繋いでから曲率を測って警告する方式も
書いてみたが、**警告を見た人間が制御点をずらして測り直す作業**に化けるだけで、
規格が線形を作る力にならない。ずらすのは計算機の仕事にする。

平面と縦断で解き方が違うのは、制約の性質が違うから。

- **縦断は凸**。どちらも y についての線形不等式なので、最小ノルム補正を
  交互に当てれば必ず実行可能点へ収束する (POCS)。
  「地盤へ引く」ステップと交互にすると、制約を満たす中で**土工量がいちばん
  小さい所**へ落ち着く。谷は跨ぎ、尾根は削る形が、目的関数から自然に出る。
- **平面の曲率制約は非凸**なので、その保証は無い。代わりに「違反した頂点を
  両隣の中点へ寄せる」= 曲率を単調に減らす操作を繰り返す。円弧の矢は
  h²/(8R) なので、寄せる割合は `1 - R/Rmin` でよく、少しずつ均す必要が無い。

**両端は固定しない。** 固定すると、尾根の上と谷底を選んだだけで
|Δy| > 延長 × imax になり、実行可能集合が空になって解が存在しなくなる。

#### 収束は回数ではなく残差で打ち切る

縦断の交互射影は線形収束なので、回数を決め打ちにすると測点が増えたときに
**黙って規格外の縦断が返る** (実測: 80 測点 / 400 スイープで 2.8 % 超過)。
残差で打ち切ること。素の射影は情報が 1 スイープに 1 測点しか伝わらず
10 万スイープ掛かるので、往復スイープ (5 万) と緩和係数 omega = 1.9
(**4,779 スイープ / 8.8 ms**) にしてある。Agmon-Motzkin の緩和法なので
(0, 2) は使ってよい。

交互射影は規格ちょうどの面へ**外側から**漸近するため、そのままだと
「ほぼ満たす」しか言えない。詰めだけ 0.1 % きつい面へ落とせば、残差は
その内側に収まって**必ず規格内**になる。テストは超過を 1 mm も許していない。

規格に載らなかったとき (制御点が急すぎるとき) は、黙って規格外の線を
返さない。実現した最小半径・最大勾配と、**制御点からどれだけ押し返されたか**を
HUD に出す。「制御点が急すぎて入らなかった」は隠すべき失敗ではなく、
**制御点を動かせという指示**そのもの。

#### 区間の種別は「地形との差」だけで決まる

「ここはトンネル」と宣言してから地面を見るのではない。規格を満たす線を
引いた結果として、地面が上に来ていればトンネル、下に離れていれば橋になる。
だから制御点を 1 つ動かすと種別がひとりでに入れ替わる。

| | |
|---|---|
| 計画高 - 地盤 > 9 m | **橋** (盛土は高さ H に対し片側 H/tanθ の用地を食う) |
| 地盤 - 計画高 > 12 m | **トンネル** |
| \|差\| < 0.7 m | 平坦 |
| それ以外 | 切土 / 盛土 |

短すぎる橋・トンネルは切盛に均す。橋台も坑口もそれ自体が高い構造物なので、
12 m 未満なら必ず切盛のほうが安い。逆に、橋に挟まれた短い切盛は橋に取り込む
(橋の途中で 6 m だけ盛土に落ちると橋台を 2 組建てることになる)。

### 4g. 回廊 — 崩れないように作る

回廊は**断面のテンプレート**で書く。ブラシで削る方式も試したが、円筒ブラシは
必ず庇を残すし、路面が刻み幅ぶん波打つ。

```
切りエンベロープ  cut[o]  = 計画高 + max(0, d - 幅/2) * tanθ
盛りエンベロープ  fill[o] = 計画高 - max(0, d - 幅/2) * tanθ
最終の地表        h[o]    = clamp(いまの地表, fill[o], cut[o])
```

書き戻しは `Edit.applyColumnHeights` — 安息角の整定と**同じ出口**なので、
路面も法面も周りの地形と地続きになり、格子が出ない。掘削量は
`Economy.chargeExcavation` を通るので、**切土が残土になって盛土に回る**という
既存の勘定にそのまま乗る。配線は 1 本も足していない。

#### 断面は「いちばん近い区間」ひとつで決める

切りと盛りを区間ごとに min / max で重ねると、路面が刻み幅ぶん波打つ。
勾配 10 % なら隣の測点とは 0.2 m 違うので、中心線上の列で
「切りの下限 = 隣の低いほう」「盛りの上限 = 隣の高いほう」になり、
上限のほうが下限より高くなって路面が常に高いほうへ寄る
(**実測: 計画高から 0.1998 m ずれた** = 勾配 × 刻み幅そのもの)。
最寄りの区間ひとつで決めれば、切りと盛りが必ず同じ区間から出るので起きない。

#### 法面は最初から安息角で切る

垂直に切って安息角 (§4c) に任せると、崩れた土が路面へ流れ込んで道が埋まる。
最初から `安息角 × ANISO_CENTER` で切っておけば、**整定は何もしない**
(min/max が冪等なので厳密に no-op。実測で動いた土量 3 m³ 未満)。
崩落の規則に例外を書くのではなく、**崩れない形で作る**。
現実の切土設計と同じ順序でもある。

法面保護工 (§4e) が入っている列はその角度を使うので、
**先に擁壁を塗っておくと回廊が細くなる**。書き戻しで保護が外れる規則に
当たるため、書き戻したあとに入れ直している。塗った面を切り直したのだから、
支えているのは新しい法面のほうだと考える。ここを入れ直さないと、
「先に擁壁を塗ってから道路を通す」が金だけ捨てる操作になる。

#### 構造物との境目は垂直に切る = 橋台・坑口

区間の端で法面を円錐状に伸ばすと、橋の取付部の盛土が**谷へこぼれ落ちて**
架けたい谷を半分埋める (実測: 深さ 30 m の谷底が 10 m から 28.8 m へ)。
トンネルはもっと悪く、坑口の切土が尾根へ 18 m 食い込んで土被りを削り、
トンネルとして成立しなくなる。

現実にこれを止めているのが橋台と坑口で、どちらも「そこで土をやめる」ための
構造物そのもの。だから構造物に接する端では法面を伸ばさず**半空間で切り**、
その面のすぐ内側の帯に擁壁と同じ保護 (88°) を入れる。費用は橋台と
トンネル支保がすでに持っている。

半空間で切ること。端の 1 区間だけを見るのでは足りない — 手前の区間の
円錐が端を越えて伸びる。保護も円盤で塗ってはいけない。路面幅ぶんしか
覆えないのに、面のほうは法面の幅 (盛土 9 m なら片側 13 m) まで広がっていて、
外側が保護されずにそこから流れ落ちる (実測: 谷底が 2.4 m 埋まった)。

#### トンネル区間は既存の台帳へ流す

回廊のトンネル区間は掘って `TunnelNetwork.recordBore` に渡すだけ。
支保も劣化も崩落も既存の規則がそのまま引き受ける。**特別扱いは書いていない。**
道路の断面は掘削ブラシより大きい (幅 9 m の道路で半径 6.1 m) ので、
土被りの基準 (半径の 1.2 倍 / 3 倍) もそのぶん上がる。長いトンネルを
一気に開けることになるので、施工班 1 班では追いつかない — §4a-3 の緊張が
そのまま道路の判断になる。

#### いまの世界では道路トンネルが出ない (既知の穴)

分類の閾値 2.85 R は山岳規格で 13.8 m、標準規格で 17.4 m。ところが
**いまの生成地形では、尾根を直角に横切っても切土は 6-11 m にしかならない。**
尾根の振幅が 17 m / 幅の尺度が 21 m と広いので、勾配 10 % の縦断が
それを登り切ってしまう (実測: z を 20 から 110 まで 15 刻みで横断、
延長 52 / 68 / 88 m のすべてで最大切土 11.1 m)。斜めの長い路線でも
最大 16.2 m で、しかも連続 12 m には届かないので切土に均される。

**閾値を下げて出やすくするのは間違い**で、そうすると出るのは
「支保も崩落も掛からない大穴」であってトンネルではない (実測: 22 m 掘って
区間 0 本)。直すなら世界の側で、尾根を高く / 狭くする
(`Generator.ts` の `17 * exp(-dr*dr)` と幅の尺度 21)。
いまの尾根は**手掘りのブラシ (半径 2.6 m → 閾値 8.3 m) 向けに作られていて**、
道路の断面には足りていない。ここは地形の設計変更なので手を付けていない。

手掘りのトンネル (A/S/D の支保が要るやつ) はいままでどおり成立する。

### 4h. 橋 — 耐力 vs 荷重

トンネルが「土被りと地質が必要支保を決める」なら、橋は
「**橋脚の足元の地質が架けられる支間を決める**」。同じ形にしてある。

| | 最大支間 | 床版 | 桁高 |
|---|---|---|---|
| RC 桁橋 | 20 m | ¥190/m² | 1.2 m |
| PC 箱桁 | 45 m | ¥340/m² | 2.2 m |
| 鋼トラス | 90 m | ¥620/m² | 3.4 m |

#### 支持力は調和平均で採る — 弱い所が決める

基礎を半径 2.6 m の円盤とみなして 19 点サンプルし、`GEO_BEARING` の
**調和平均**を採る。算術平均ではない。

岩 3.0 / 土 2.0 / 軟弱 0.05 MPa なので、フーチングの半分が軟弱層に掛かると

| | 支持力 |
|---|---|
| 算術平均 (並列ばね) | 1.53 MPa — ほぼ無傷 |
| **調和平均 (直列ばね)** | **0.098 MPa — 1/15 に急落** |

急落するほうが正しい。基礎の下の一部だけが柔らかいとき、沈下を決めるのは
**いちばん柔らかい所**で、そこだけ沈めば不同沈下になって上部工が保たない。
算術平均にすると「半分軟弱層でも半分岩なら建つ」になり、谷底の軟弱層が
まったく判断に効かなくなる。

#### 支間表が意思決定になる理由

支間を伸ばすと橋脚の本数が減り、**落ちる位置が変わる**。
支間表は安い順に試され、橋脚が立つ最初の案が選ばれる。

- 岩の谷 → いちばん安い RC 桁で架かる
- 橋脚の落ちる所**だけ**が軟弱層 → PC 箱桁に伸ばすと跨げる
- 軟弱層の下に岩 → 深礎で下ろす (1 m につき ¥2,400 / 0.25 時間)
- 深礎の限界 24 m まで下ろしても届かない → **立たない**。線形を動かすしかない

「どこに何があるか」を知るにはボーリング (§5) が要る。見積りは
**既知の情報だけ**で作る — 未調査の深さは「地表の地質がそのまま下へ続く」と
みなすので、HUD には `橋脚 2 基が未調査 — 支持力は推定` と出る。
着工時は真の場で評価し直すので、そこで深礎が伸びるか、橋脚が立たない。

橋台の支持力は見ない。橋台は橋の両端 = 路面が地山に取り付く所に立つので、
そこは必ず回廊が均した地面になっている。橋台まで判定に入れると、
「谷を渡りたいのに渡り始める場所が悪くて架けられない」という、
線形を動かしても直せない行き止まりが増えるだけで判断が 1 つも増えない。

#### 後から足元を掘れば落橋する

トンネルとまったく同じ配線。編集の AABB で `SpatialIndex` を引き、
当たった**橋脚だけ**を再評価キューに積む。橋脚の足元を掘れば支持力が落ち、
地盤が下がれば橋脚が伸びて荷重が増える。荷重が耐力を割ると健全度が
不足の 2 乗で落ちて落橋する。支持力不足の橋脚は赤く明滅し、
崩落が近いほど速い (支保のリングと同じ規約)。**特別扱いは書いていない。**

### 5. 分からないものは見せない

地質の既知/未知はセル単位では保存しない。描かれている地表は定義上
すべて露出面なので、見えている所は常に真の色でよい。分からないのは
「まだ掘っていない面の裏側」だけなので、保持するのはボーリングの
柱状図だけで足りる。

断面ビューは、各画素の信頼度を「露出面からの距離」と「ボーリングからの
距離」の大きいほうで決め、低い所を灰色ハッチに落とす。密度場の値が
ほぼ「表面までの距離」なので、掘った坑道の壁も自動的に露出面として
扱われる。トンネルを掘れば周囲の地質が分かるようになる。

`Alignment.ts` は地形を一切知らない純粋モジュール (地盤高は関数で受ける)
なので、規格の解き方だけを単体で試験できる。

初期資金は道路が入ったときに 250,000 から **450,000** へ上げた。道路 1 本で
土工・トンネル・橋・舗装に 20-30 万かかり、そのうえトンネルの支保が乗るので、
旧来の額では線形を引く前に詰む。

## まだ作っていないもの (次弾)

- **交通**: いまは道路を通しても「通れる」以上のことが起きない。
  起終点と所要時間が付いて初めて、遠回りの線形と高い規格の差が
  収入として返ってくる。
- **鉄道**: 規格 (最小半径・最大勾配) の枠組みはそのまま使える。
  勾配の上限がずっと厳しくなるので、同じ地形でトンネルと橋の比率が変わる。

## 検証

- `npm test` — 純粋な部分を数値で固定している (100 件)。
  - 隣接チャンクの共有境界で頂点位置がミクロン以内、法線と地質重みが
    ビット単位で一致すること。ここが壊れると地形に割れが出るが、
    描画を見て気づくのは難しい。
  - 必要支保レベルの判定規則。
  - ボーリングの層序と信頼度。
  - **斜面にトンネルを掘る通しテスト** (5 件)。毎フレーム掘って毎フレーム
    崩すループを回さないと出ないバグがあり、単体テストでは 1 件も
    引っかからなかった。掘り進めること・土被りが付いてトンネルとして
    成立すること・ヘッドが後退しないこと・崩れる範囲が有限で止まること・
    動いた土量が掘削量とかけ離れないことを押さえる。
  - 法面保護工 (12 件)。工法ごとの角度で止まること、前払いで順番が来るまで
    効かないこと、施工班が支保と共有の 1 班であること、塗った上を掘り抜くと
    掘った列だけ保護が外れること。terrain 層へ写した角度が本体とずれて
    いないことも突き合わせる (ずれると崩落の角度と表示が食い違う)。
  - 安息角 (15 件)。角度そのものより**平面性と異方性**を厳しく見る。
    崩れて積もった土が崩積土になり、削れて露出した面は元の地質のままで
    あることも押さえる。
    崩れた法面の 2 階差分が 1 cm 未満であること、方位で安定角が 1.5° 以上
    変わらないこと、体積が保存すること、二度目の整定が完全な no-op であること
    (冪等でなくなると誤差が毎フレーム積み上がる)、坑道が埋まらないこと、
    ワールドの外周が流れ落ちないこと。
  - **線形** (17 件)。規格を**超過 0 で**満たすこと (詰めの 0.1 % を外すと
    ここが落ちる)、直角やつづら折りの制御点でも発散しないこと、
    曲げる必要が無ければ制御点をほぼ通ること、短すぎる橋・トンネルが
    出ないこと。
  - **橋** (18 件)。支持力がフーチングの一部の軟弱層で急落すること
    (算術平均に変えるとここが落ちる)、深礎が支持層の上端で止まること、
    短支間で立たない谷が長支間なら渡れること、あとから足元の地質が
    変われば落橋に向かうこと。
  - **道路の施工** (13 件)。路面が計画高で平らになること (刻み幅ぶんの
    波打ちが出れば 0.2 m 級で落ちる)、切った法面が安息角で寝ていて
    **整定が何もしない**こと、橋台の面が整定でも落ちないこと、
    谷が埋まらないこと、掘った土が既存の Economy を通って残土になること、
    トンネル区間が既存の台帳に載って支保の対象になること。
- 見た目は Playwright でスクリーンショットを撮って確認する。
  `window.__game` に `view()` / `carve()` / `bore()` / `road()` の
  デバッグ API がある。
  `?mat=plain` `?mat=normal` でシェーダを外し、格子が見える原因が
  ジオメトリ側かシェーダ側かを切り分けられる。
